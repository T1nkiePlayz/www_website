Embermark Forgery.

A smaller game project created to learn, experiment and gain experience taking a game from an idea toward something that can actually be finished and released.

EMBERMARK
// overview

Small enough to finish. Big enough to learn.

Embermark Forgery exists for a practical reason: building a huge game like Aetheria is very different from finishing a smaller game.

This project gives me a smaller space to practise the complete development process — deciding what belongs, implementing mechanics, creating content, testing, fixing, polishing and working toward a release.

// purpose

Learning through completion.

Large projects can make it easy to spend months building foundations without reaching a playable result. Embermark pushes in the opposite direction by keeping the scope manageable and forcing decisions about priorities and boundaries.

// experimentation

Trying ideas without endless scope.

Mechanics can be tried, changed or removed as I learn what makes the game work. The important part is keeping the project small enough that experimentation doesn't become endless expansion.

// bigger_picture

Experience for future projects.

Planning, architecture, game feel, content pipelines, debugging and release preparation are skills that become increasingly important as projects grow.

// lessons

What I'm practising.

  • Scoping a project realistically
  • Reusable game systems
  • Balancing code and content
  • Testing and iteration
  • Polishing a playable experience
  • Working toward release
// relationship

Before Aetheria.

Embermark isn't intended to replace Aetheria. It is a smaller step that lets me practise shipping and learn from mistakes before applying those lessons to a much larger project.

// project_note

A smaller project can teach bigger lessons.

The point is to experience the parts of game development that only become obvious when you try to turn an idea into a complete game.
